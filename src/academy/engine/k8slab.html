Kubernetes, behind the scenes

First time in the detailed lab?

This is an optional practice area. The Kubernetes lessons take you back to the beginner path.

  1. Tutorial: pick one question. Read the explanation below the drawing. Use Next or the arrow keys to move one idea at a time.
  2. Playground: choose Deploy nginx ×2. Two pods appear. Click one to delete it, then watch a replacement appear. Next choose Expose web (LoadBalancer) to give traffic a way in.
  3. Manifests: choose a template before editing. Change one value at a time and read the validation messages.

These commands affect only this simulated cluster. Pod and traffic colors are also explained in the labels and event output. Use Guided learning for the slower Pause / Next step practices.

    ← → to step  ·  space to autoplay  ·  click a step to jump

    A simulated cluster that behaves like a real one: controllers reconcile, the scheduler places pods, traffic flows. Type real kubectl / helm commands in the terminal, or use the buttons. Click a node to drain / uncordon it, click a pod to delete it.

    Colours

    green = requests from outside (browser → Ingress/LoadBalancer → Service → pod) · blue = pod-to-pod calls through a Service · amber = egress to the internet · red = dropped (no controller, no endpoints)

    Write real Kubernetes manifests in the editor (several documents separated by ---). They are linted like a CI pipeline would, then synced into the simulated cluster the way kubectl apply --prune / Argo CD does: the editor is the source of truth, anything you remove gets pruned, changes roll out live.

    What is simulated

    Deployment · StatefulSet · DaemonSet (one pod per node) · Job (runs to Completed) · Service (selector, type, targetPort) · Ingress (needs an ingress controller Deployment) · ConfigMap / Secret (missing ref → CreateContainerConfigError) · PersistentVolumeClaim (missing → Pending) · HPA (shown) · rolling updates on image or label change · label selectors are matched for real, so a typo means 0 endpoints.

    Traffic is inferred from env values: http://api → calls Service api; a URL with a real domain → egress to the internet. Click a node to drain it, click a pod to delete it.
