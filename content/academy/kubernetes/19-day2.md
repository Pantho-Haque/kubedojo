<p class="lead">Building a cluster is <b>day 1</b>. Keeping it healthy for months is <b>day 2</b>, and that's the real job. Here's what to set up and the routine to follow.</p>

kubectl top pods -A</pre><button class="copy">Copy</button></div>
<label class="task"><input type="checkbox" data-task="d-k9s"><span>Install k9s, a terminal dashboard. It's honestly fun.</span></label><div class="cmd"><pre tabindex="0">brew install k9s &amp;&amp; k9s</pre><button class="copy">Copy</button></div>
<label class="task"><input type="checkbox" data-task="d-prom"><span>Monitoring and alerts: Prometheus + Grafana + Alertmanager in one chart</span></label><div class="cmd"><pre tabindex="0">helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm install mon prometheus-community/kube-prometheus-stack -n monitoring --create-namespace
kubectl -n monitoring get secret mon-grafana -o jsonpath='{.data.admin-password}' | base64 -d; echo

<h2>💾 2 · Backups (a backup you've never restored is just a hope)</h2>
<table><tr><th>What</th><th>How</th></tr>
<tr><td>Cluster state (etcd)</td><td>The single-server k3s setup here uses SQLite. Follow the <a href="https://docs.k3s.io/datastore/backup-restore" target="_blank" rel="noopener">K3s backup and restore instructions</a>: preserve the database directory and <code>/var/lib/rancher/k3s/server/token</code>, store a copy off the node, and test restoring it. With embedded etcd: <code>sudo k3s etcd-snapshot save</code>. With kubeadm: <code>etcdctl snapshot save</code>.</td></tr>
<tr><td>Your manifests</td><td>Keep <b>all</b> YAML and Helm values in git. Then the cluster itself can be rebuilt from scratch.</td></tr>
<tr><td>App data (PVCs)</td><td>Use database-aware backups for databases. Tools such as Velero can back up resources and supported volumes when their storage integration is configured. Test a restore; a PVC by itself is not a backup.</td></tr></table>

<h2>⬆️ 3 · Upgrades</h2>
<p>Kubernetes ships a new minor version about 3 times a year, and each one is supported for roughly a year. So plan an upgrade every few months.</p>
<ul><li>Go <b>one minor version at a time</b> (1.33 → 1.34, never skip one).</li>
<li><b>Control plane first, then workers.</b></li>
<li>Read the release notes for removed APIs before you upgrade.</li></ul>
<label class="task"><input type="checkbox" data-task="d-drain"><span>Upgrade each node safely: move its pods away, upgrade it, let pods back</span></label><div class="cmd"><pre tabindex="0">kubectl drain w1 --ignore-daemonsets --delete-emptydir-data   # move pods off w1
# upgrade w1 (k3s: re-run the install script with INSTALL_K3S_VERSION=&lt;next version&gt;)
kubectl uncordon w1                                              # allow pods back</pre><button class="copy">Copy</button></div>
<p style="font-size:15px">Add a <b>PodDisruptionBudget</b> to important apps so a drain never takes all their replicas down at once.</p>
<h2>🔐 4 · Certificates & security</h2>
<ul><li><b>cert-manager</b> + Let's Encrypt gives your websites HTTPS certificates that renew themselves.</li>
<li>The cluster's internal certificates usually last <b>1 year</b>. Regular upgrades renew them (with kubeadm, check with <code>kubeadm certs check-expiration</code>).</li>
<li>Keep the node operating systems and your container images patched.</li></ul>
<div class="cmd"><pre tabindex="0">helm repo add jetstack https://charts.jetstack.io
helm install cert-manager jetstack/cert-manager -n cert-manager --create-namespace --set crds.enabled=true</pre><button class="copy">Copy</button></div>
